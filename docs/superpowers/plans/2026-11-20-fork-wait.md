# Fork/Wait Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `SYS_FORK` and `SYS_WAIT` so a ring-3 process can clone itself, collect a child's exit status, and be reaped correctly by its parent.

**Architecture:** Copy the parent's live syscall trap frame onto a fresh child kernel stack so the child resumes after `int 0x80` with `rax = 0`. Clone the user address space with deep-copied page tables and data pages (no COW), clone the fd table through the existing `fd_clone_process()`, add `ppid` links, and make the idle reaper skip parented zombies until `wait` consumes them.

**Tech Stack:** x86_64 freestanding C (`zig cc`), GNU assembly, MSYS2 host GCC for tests, QEMU boot gate.

**Spec:** `docs/specs/process-fork-wait-design.md`

## Global Constraints

- Append-only syscalls: `SYS_FORK 14`, `SYS_WAIT 15`. Never renumber 1–13.
- Do not change `USER_CODE_VA`, `USER_STACK_VA`, MLFQ policy/counters, fd refcount contract, embedded shell image, or `tests/run_all.bat`.
- Batch files from `cmd /c ...`, never PowerShell `&&`.
- UP-only; no SMP, PCID, COW, or page-fault handler.
- Every task ends with: host tests green, full build green, QEMU boot gate green.

## Review Focus

- A forked child writing its stack must not corrupt the parent → Task 2 test asserts distinct physical frames and independent contents.
- Idle reaper stealing a zombie before `wait` → Task 3 test asserts parented zombie survives `scheduler_reap_zombies()`.
- `wait` returning before the child actually exits → Task 4 test asserts the caller is `PROC_BLOCKED` until child exit, then wakes.
- Orphaned child leaking a slot/zombie when its parent exits first → Task 3 test asserts reparent-to-0 and eventual reaping.
- OFD refcount drift from fd cloning → Task 4 test asserts refs increase by one per cloned file fd and drop to zero on both reaps.

### Task 4: `SYS_FORK` / `SYS_WAIT` dispatch

- [ ] **Step 1: Write the failing tests**

- [ ] **Step 2: Run test to verify it fails**

- [ ] **Step 3: Implement**
