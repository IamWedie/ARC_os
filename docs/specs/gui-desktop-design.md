# Design: Graphical Desktop (M1 + M2)

Status: Proposed (M0). Implements roadmap M1/M2; see
`docs/specs/arc-os-24-month-roadmap.md`.

## Intent

ARC OS currently exposes only an 80x25 VGA text console plus a ring-3 serial
shell. M1 and M2 deliver a modern, macOS-inspired graphical desktop at
1920x1080x32 in QEMU: a stable framebuffer, anti-aliased text, mouse input, a
kernel-mode compositor, windows, a dock, and a menu bar. The result must be
visually real and testable by deterministic screendump gates, while preserving
every existing serial shell behavior and gate.

## Goals

- M1: 1920x1080x32 Bochs VBE framebuffer with fallback to 1280x720 then
  1024x768; RAM back buffer; dirty-rect present; OFL pre-rasterized font with
  8-bit coverage alpha blending; premultiplied-alpha primitives; 60 Hz
  LAPIC-timer frame pacing that skips clean frames.
- M2: PS/2 mouse (IRQ12) with decode/clamp/acceleration; kernel-mode
  compositor with 16-window table, Z-order, per-window ARGB surfaces, damage
  tracking; rounded corners, cached 9-slice shadows, traffic-light buttons,
  active/inactive title bar; translucent menu bar with blur-behind; Dock with
  magnification and running indicator; eased animations; kernel-mode apps
  (About, Notes, Files, System Monitor showing RAM/FPS/uptime).
- Preserve ring-3 serial shell and all existing gates; keyboard goes to focused
  text field, otherwise to shell.
- Scalar code only through M2; no SSE/MMX/AVX in kernel text (ADR-004). SIMD
  deferred to M10 under ADR-012.

## Non-goals

- No Win32/POSIX GUI compatibility, no networking/audio, no real GPU driver.
- No SMP (M10), no userspace GUI syscalls (M6), no persistent GUI state (M7).
- No changes to existing syscalls 1-16, fd/refcount contract, MLFQ
  policy/counters, `USER_CODE_VA`/`USER_STACK_VA`, embedded shell blobs, or
  `tests/run_all.bat`.
- No UEFI/GOP/Multiboot2 hardware path in M1/M2 (M3).

## Design

### Display (M1)

- Program Bochs VBE DISPI for 1920x1080x32; verify readback; fall back to
  1280x720, then 1024x768. LFB physical base from PCI BAR0 of vendor `0x1234`.
- QEMU args per roadmap M1 step 2: `-vga none -device bochs-display,
  vgamem=67108864`. **Spike note (ADR-007, risk-log):** on QEMU 11.1.0 this
  device did not respond to legacy DISPI I/O ports 0x1CE/0x1CF; M1 must verify
  and, if needed, use BAR2 MMIO DISPI registers before relying on this path.
- Allocate a RAM back buffer from PMM (prefer 2 MiB pages). All drawing targets
  the back buffer; `gfx_present(rect)` copies only dirty rectangles to the LFB.
- Dirty-rect list with merge logic (host-testable, pure).
- Font: embed one OFL-licensed font (Inter or similar), pre-rasterized at
  12/14/18/24 px as 8-bit coverage bitmaps generated by `tools/` and committed
  as C arrays. Render by alpha blending coverage against any background.
- Premultiplied-alpha pixel/fill primitives; scalar only.
- 60 Hz frame pacer driven by LAPIC timer; skip frames when nothing is dirty.

### Compositor and shell (M2)

- PS/2 mouse driver: IRQ12 via IOAPIC, 3-byte packets, clamping, acceleration;
  pure decode function for host tests.
- Compositor: window table (16), Z-order, per-window ARGB surfaces in RAM,
  premultiplied-alpha blend, damage tracking.
- Visuals: cached rounded-corner masks (radius 10), cached 9-slice drop
  shadows, traffic-light buttons, active/inactive title bar.
- Menu bar (28 px, translucent): logo, app name, clock; blur-behind via box
  blur on a downscaled cached copy.
- Dock: centered pill, icon magnification on hover, running indicator.
- Animations: ease-out/spring easing driven by frame pacer for open/close/
  minimize.
- Kernel-mode apps: About, Notes, Files, System Monitor (RAM used/free, FPS,
  uptime; per-core comes in M10).
- Keyboard routing: focused text-field window gets keys; otherwise keys reach
  the ring-3 shell so existing gates stay green.

### Interfaces (planned, refined during implementation)

- `gfx`: `gfx_init`, `gfx_fb`, `gfx_clear/fill_rect/putpixel/blend_pixel`,
  `gfx_fill_rect_alpha`, `gfx_present`, dirty-rect list/merge, font draw.
- `mouse`: `mouse_init`, `mouse_state_get`, pure decode/clamp/accelerate.
- `gui/compositor`: window table, hit-test, Z-order, drag, event routing,
  tick/present.

## Verification

- Host: `tests/test_gfx.c` (suite 12, append-only in `run_tests.bat`) for clip,
  fill, alpha blend math, dirty-rect merge, font coverage blend. `tests/test_gui.c`
  (suite 13) for hit-testing, Z-order, drag, mask math, easing, mouse decode.
- QEMU gates: `tests/boot_test_gui.py` screendump pixel assertions (wallpaper,
  rect, glyph pixel); mouse move/click injection via monitor for window
  appear/drag/close/dock hover.
- Existing gates remain green: `tests/run_all.bat` frozen, fork gate, exec gate.
- `tests/run_all.bat` is never modified; GUI gates are separate scripts.
- M3 onward: real-hardware checklist per roadmap section 8, logged in
  `tasks/hardware-log.md`.
