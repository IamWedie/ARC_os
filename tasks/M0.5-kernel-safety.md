# ARC OS --- M0.5 Kernel Safety & Reliability

**Purpose:** Fix the correctness, memory-safety, privilege-boundary, and
data-integrity issues identified in the source review before continuing
the 24-month feature roadmap.

**Scope:** Remediation only. Do not add new user-facing features,
drivers, GUI capabilities, filesystems, networking, SMP, SIMD, or new
syscalls in this milestone.

**Starting point:** Re-check the current `main` branch before doing
anything. The earlier roadmap names `b25aac8`; the source review was
performed against a later repository state. Do not assume either commit
is still HEAD.

**Working rule:** One task at a time. Implement, test, report, and stop
for approval after each task. Do not silently skip a task or weaken an
existing test/gate to make it pass.

------------------------------------------------------------------------

## 0. Agent operating contract

The coding agent MUST:

1.  Inspect the current branch, commit, working tree, build

    editing.
2.  Confirm that the findings below still apply to the current code. If
    a finding is already fixed, show the exact implementation and test
    proving it, then mark it `VERIFIED FIXED` without rewriting it.
3.  Work only on the task currently approved by the user. Do not
    implement later tasks opportunistically.
4.  Write a short design note before changing architecture-sensitive
    code.
5.  Add regression tests for every bug fix. Prefer host-testable pure
    helpers where practical, but also test the real kernel
    implementation where possible.
6.  Never weaken, delete, skip, or change the meaning of an existing
    test or QEMU gate just to obtain a green result. If an existing test
    is incorrect, explain why and request approval before changing it.
7.  Run the narrowest relevant test after each change. At each task
    boundary, run the full build and the existing required test gates
    that are feasible.
8.  Record exact commands, exit codes, and relevant output. Do not say a
    test passed if it was not run.
9.  Do not change syscall numbers or the existing syscall ABI. This
    milestone adds no syscalls.
10. Do not reformat or refactor unrelated files. Keep diffs small and
    reviewable.
11. Do not modify disk images or test real disks except explicitly
    designated disposable test images.
12. Stop immediately if a task requires changing a frozen decision,
    public ABI, boot contract, or test contract. Explain the conflict
    and ask for approval.
13. Do not push, merge, tag, or modify the user's roadmap unless
    explicitly asked.
14. Never claim QEMU or real-hardware validation based only on
    compilation or host tests.

## 2. P0 --- User-pointer isolation at the syscall boundary

**Why first:** A ring-3 process must not be able to make the kernel read
from or write to arbitrary kernel virtual addresses through syscall
pointer arguments.

Relevant areas identified in the review: - `kernel/syscall.c`:
`SYS_WRITE`, `SYS_READ`, and path/name arguments for open, delete,
rename, and related calls. - `kernel/fd.c`: file and terminal read/write
paths. - `kernel/scheduler.c`: child wait status output. -
`kernel/exec.c`: existing user-memory reading logic that may be
reusable, but is not a general syscall boundary.

### Tasks

-   [ ] Re-inspect every syscall and enumerate every argument that is a
    user pointer, including nested structures and strings.
-   [ ] Define the user address range and overflow-safe range-validation
    rules from the actual address-space implementation. Do not invent a
    limit.
-   [ ] Design generic `copy_from_user`, `copy_to_user`, and bounded
    `copy_user_string` helpers.
-   [ ] Helpers must handle zero length, null pointers according to the
    syscall contract, integer overflow, page crossings, unmapped pages,
    supervisor-only mappings, and read-only destination mappings.
-   [ ] Copy user data into kernel-owned buffers before passing it to
    kernel subsystems. Copy results back only through the validated
    copy-out helper.
-   [ ] Audit every syscall path, including error paths. No raw user
    pointer may be dereferenced by kernel code.
-   [ ] Audit `fd_read`, `fd_write`, exec argument loading, path
    handling, and wait-status output for indirect pointer dereferences.
-   [ ] Add adversarial tests: kernel-space pointer, unmapped pointer,
    pointer crossing into an unmapped page, read-only output page,
    unterminated string at the maximum length, zero-length buffer, and
    near-maximum address/length overflow.
-   [ ] Add a QEMU user-mode test proving invalid user pointers
    terminate/fail the offending syscall or process without exposing or
    corrupting kernel memory.

**Exit criteria:** All syscall user pointers are validated and copied
safely; adversarial tests pass; a bad user pointer cannot crash the
kernel or read/write kernel memory.

**Do not proceed** if any syscall pointer path remains unaudited.

## 3. P0 --- Validate filesystem metadata before trusting it

**Why:** On-disk metadata is untrusted input. Mounting a corrupt image
must not write outside the filesystem bitmap or filesystem arena.

Relevant areas identified: - `kernel/fs.c`: mount path loading directory
records. - `fs_bmap_set`, `fs_slot_read`, and `fs_slot_write`: block and
extent handling.

### Tasks

-   [ ] Trace the complete on-disk format and document field sizes,
    valid values, block numbering, and maximum file size.
-   [ ] Implement a validation pass that runs before any on-disk record
    can mutate allocator/bitmap state.
-   [ ] Validate every record's type/state, name termination and length,
    start block, block count, file size, and all arithmetic for
    overflow.
-   [ ] Validate extents are within the volume, do not overlap reserved
    metadata, and do not overlap one another unless the format
    explicitly permits it.
-   [ ] Validate that file size is consistent with allocated block count
    and the filesystem's maximum file size.
-   [ ] Make bitmap access reject out-of-range block indices. Do not
    rely only on mount-time validation.
-   [ ] Make read/write paths independently validate slot indices,
    offsets, lengths, and extent bounds.
-   [ ] Reject malformed volumes cleanly. Do not partially mount them
    and do not attempt repair automatically.
-   [ ] Add tests for truncated directory data, huge block counts,
    out-of-range start blocks, arithmetic overflow, overlapping extents,
    unterminated names, inconsistent size/block counts, and random
    corrupt images.
-   [ ] Run corruption tests under sanitizers where the host test setup
    supports them.

**Exit criteria:** Malformed images are rejected without out-of-bounds
access, memory corruption, infinite loops, or writes to the image.

## 4. P0 --- Prevent destructive automatic formatting

**Why:** The reviewed code used LBA 0 for the filesystem superblock and
could format a detected disk when no matching ARCFS superblock was
found. On a real disk, LBA 0 may contain the MBR or protective MBR.

### Tasks

-   [ ] Re-inspect disk discovery, mount, format, and `run.bat` disk
    attachment behavior.
-   [ ] Remove automatic formatting of unknown or unrecognized disks.
-   [ ] Move the filesystem to an explicitly designated test image or
    documented partition/offset. Never assume LBA 0 is available.
-   [ ] Add capacity and range checks before every filesystem disk
    operation.
-   [ ] Require an explicit format action against a known disposable
    target. No implicit format on boot.
-   [ ] Add tests proving an unknown disk is left byte-for-byte
    unchanged.
-   [ ] Add a test image with a recognizable MBR/protective MBR and
    prove filesystem initialization does not overwrite it.
-   [ ] Document the exact safe QEMU disk-image creation and attachment
    procedure.

**Exit criteria:** Booting with an unknown disk never writes to it;
filesystem formatting is explicit and restricted to the intended test
target.

## 5. P1 --- IDT completeness and unexpected interrupt handling

Relevant areas identified: - `kernel/idt.c`: all IDT entries were
initialized as present with a zero handler address. - `kernel/lapic.c`:
APIC spurious vector configuration.

### Tasks

-   [ ] Enumerate every CPU exception, IRQ, syscall vector, local APIC
    vector, and reserved vector used by the kernel.
-   [ ] Install valid handlers for all vectors that can be delivered.
-   [ ] Mark truly unused IDT entries not-present, or route them to a
    safe default handler where appropriate.
-   [ ] Add an explicit APIC spurious-vector handler for the configured
    vector. Follow the APIC's spurious-interrupt EOI rules.
-   [ ] Ensure unexpected vectors produce a controlled diagnostic rather
    than jumping to address zero.
-   [ ] Add a test or QEMU injection strategy for the default/unexpected
    vector path and spurious-vector path, where feasible.

**Exit criteria:** No present IDT gate points to address zero; all
configured interrupt vectors have intentional handling.

------------------------------------------------------------------------

## 6. P1 --- Recover from user-mode exceptions without halting the OS

Relevant areas identified: - `kernel/exceptions.c`: user-mode exceptions
were reported but then reached the common halt path. - `dump_trace()`:
frame-pointer walking must not trust a ring-3 process's RBP as a kernel
backtrace.

### Tasks

-   [ ] Separate kernel-originated exceptions from ring-3 process
    exceptions using the actual saved privilege frame.
-   [ ] Keep kernel exceptions fatal and diagnostic.
-   [ ] For user exceptions, record process identity and fault
    information, mark the process terminated, release/reap it safely,
    and schedule another runnable process.
-   [ ] Do not walk a user-controlled RBP chain as a kernel stack trace.
-   [ ] Ensure exception reporting itself cannot fault recursively on
    invalid user state.
-   [ ] Add QEMU tests where a user program triggers an invalid opcode
    and a user-mode page fault while another process or shell remains
    usable.
-   [ ] Verify process resources, address spaces, file descriptors, and
    child wait status are handled consistently.

**Exit criteria:** A crashing user process is terminated and reaped; the
kernel and unrelated processes continue running. Kernel-mode faults
still enter the fatal path.

## 7. P1 --- Fix interrupt-to-C stack alignment

Relevant areas identified: - `kernel/isr.S`: register-save macros and
interrupt/syscall stubs call C code without a demonstrated SysV ABI
alignment guarantee. - Kernel-thread initial frame construction in
process setup may also need a correct C-entry trampoline.

### Tasks

-   [ ] Calculate and document stack alignment for every entry path:
    ring-3 syscall, ring-3 exception, kernel-mode IRQ, timer interrupt,
    and any path that calls C.
-   [ ] Confirm the compiler ABI requirements used by the actual
    toolchain and build flags.
-   [ ] Add assembly wrappers that preserve the interrupt frame, align
    the stack before calling C, and restore the original frame/stack
    correctly.
-   [ ] Do not assume `-mno-sse` makes ABI violations harmless.
-   [ ] Audit context-switch paths to ensure alignment is preserved
    across scheduling.
-   [ ] Audit kernel-thread startup frames. If the API is active or
    intended to be active, use a trampoline that enters the C function
    with correct ABI alignment.
-   [ ] Add compile-time/runtime assertions or a small assembly/C test
    where practical.
-   [ ] Run syscall, timer, exception, fork/exec, and scheduler QEMU
    gates after the change.

**Exit criteria:** Every assembly-to-C call site satisfies the target
ABI, and interrupt return/context switching remains correct.

## 8. P1 --- PMM reserved-frame safety

Relevant area identified: - `kernel/pmm.c`: free path can clear bitmap
bits without proving the frame was allocated by the PMM; reserved and
allocated states are not distinguished.

### Tasks

-   [ ] Reconstruct the physical memory map and PMM ownership rules from
    the current implementation.
-   [ ] Define which frame states are free, allocated, reserved, and
    unavailable, or provide equivalent metadata that prevents
    reserved-frame release.
-   [ ] Reject unaligned addresses, zero/invalid counts, overflow,
    out-of-range spans, and freeing frames not owned by the allocator.
-   [ ] Ensure freeing a range cannot release kernel, bootloader,
    firmware, MMIO, page-table, or other reserved memory.
-   [ ] Add tests against the real `kernel/pmm.c` implementation using a
    synthetic memory map; do not rely only on `tests/pmm_stub.c`.
-   [ ] Test double free, partial overlap, reserved frame free,
    unaligned free, boundary range, and allocation/free accounting.

**Exit criteria:** PMM cannot free reserved or unowned frames, and the
real allocator has direct regression coverage.

## 9. P1 --- Page-table mapping invariants

Relevant area identified: - `kernel/pagetable.c`: mapping can overwrite
an existing present PTE; alignment and intermediate permission
propagation need explicit rules. - `kernel/address_space.c`: user
mapping arguments need strict validation.

### Tasks

-   [ ] Document `pt_map` ownership semantics: who owns mapped frames,
    whether replacement is allowed, and who frees replaced frames.
-   [ ] Reject unaligned virtual/physical addresses and invalid page
    counts rather than silently masking address bits.
-   [ ] Reject duplicate mappings by default, or provide a separate
    explicit replacement API with safe ownership semantics.
-   [ ] Ensure intermediate page-table permissions are compatible with
    leaf permissions, including USER and RW propagation.
-   [ ] Validate user mapping range, page count, arithmetic overflow,
    and forbidden regions in `as_map_user`.
-   [ ] Add tests for duplicate maps, unaligned addresses, zero pages,
    overflow, read-only then writable mappings, supervisor/user
    permission separation, and unmap/free behavior.
-   [ ] Verify changes against the actual address-space layout and
    canonical-address rules.

**Exit criteria:** Mapping APIs reject invalid inputs and preserve the
documented permission and ownership invariants.

## 10. P2 --- Filesystem initialization and persistence correctness

Relevant areas identified: - `kernel/fs.c`: bitmap allocation was used
before its allocation result was checked. - Format/initialization
ordering could suppress persistence of initial file contents. - Some
disk-write failures were not propagated to callers.

### Tasks

-   [ ] Check every allocation result immediately before dereferencing
    it; unwind partially initialized state safely.
-   [ ] Define a deterministic format sequence: initialize metadata and
    data, persist required structures, and write the valid
    superblock/commit marker last.
-   [ ] Ensure initial files and their contents are persisted, not only
    their directory records.
-   [ ] Propagate ATA/block-device write and flush errors all the way to
    filesystem callers.
-   [ ] Ensure an operation is not reported successful when persistence
    failed.
-   [ ] Add fault-injection tests for allocation failure and disk I/O
    failure at each initialization/persistence stage.
-   [ ] Verify reboot persistence using a disposable QEMU image.

**Exit criteria:** Initialization fails safely on allocation or I/O
errors, and successful writes survive reboot in the test image.

------------------------------------------------------------------------

## 11. P2 --- ATA PIO bounds and protocol checks

Relevant area identified: - `kernel/ata.c`: request bounds were not
checked against device capacity/LBA28 limits; data transfer
readiness/error handling needed strengthening.

### Tasks

-   [ ] Retain the device capacity reported by IDENTIFY and use it for
    every request.
-   [ ] Validate sector count, starting LBA, end-LBA overflow, device
    capacity, and LBA28 limits before issuing commands.
-   [ ] Validate status/error bits and DRQ readiness before transferring
    data.
-   [ ] Add bounded timeouts to every wait loop and return useful error
    codes.
-   [ ] Ensure partial failures propagate through the block/filesystem
    layers.
-   [ ] Add host-testable request-validation tests and QEMU tests for
    invalid/out-of-range requests where feasible.

**Exit criteria:** Invalid requests are rejected before hardware I/O;
valid reads/writes check protocol status and report failures accurately.

------------------------------------------------------------------------

## 12. P2 --- Move rendering out of hard interrupt context

Relevant areas identified: - `kernel/lapic.c`: timer handler calls
graphics tick logic. - `kernel/gfx.c`: frame tick can call GUI frame
logic. - `kernel/gui.c`: frame path performs substantial
drawing/compositing and full-screen presentation.

### Tasks

-   [ ] Map the complete timer → graphics → GUI call chain and identify
    all work performed at interrupt level.
-   [ ] Restrict the timer ISR to acknowledging the interrupt, updating
    minimal counters/state, and waking/signalling deferred work.
-   [ ] Move frame composition and presentation to a safe non-ISR
    execution context.
-   [ ] Define synchronization between input events, window state, and
    the compositor. Avoid introducing unprotected shared-state races.
-   [ ] Keep the current visual output and existing QEMU gate behavior.
-   [ ] Add instrumentation for ISR duration and compositor duration.
-   [ ] Add a regression gate proving timer/scheduling/input continue
    while a full frame is rendered.

**Exit criteria:** No full GUI draw, blend, composite, or framebuffer
copy runs in hard interrupt context.

M0.5 is complete only when all applicable items below are demonstrated:

-   [ ] No syscall dereferences an unvalidated user pointer.
-   [ ] Adversarial user-pointer tests pass without kernel memory
    disclosure/corruption.
-   [ ] Corrupt filesystem images are rejected safely.
-   [ ] Unknown disks are never automatically formatted or written.
-   [ ] No present IDT entry has a null handler.
-   [ ] Configured APIC spurious vector has intentional handling.
-   [ ] User-mode exceptions terminate the offending process without

-   [ ] Assembly-to-C call paths satisfy the target ABI stack-alignment

-   [ ] PMM cannot free reserved/unowned frames; real PMM tests pass.
-   [ ] Page-table APIs enforce alignment, duplicate-map, ownership, and

-   [ ] ATA validates device bounds and transfer status.
-   [ ] GUI rendering is not performed in hard interrupt context.
-   [ ] Full build succeeds.
-   [ ] All existing host tests and `tests/run_all.bat` pass.
-   [ ] GUI QEMU gate passes.
-   [ ] Relevant syscall, process, filesystem, and scheduler QEMU gates

## 15. Revised order for the existing 24-month roadmap

Keep the original M1--M12 goals, but change sequencing:

1.  **M0 baseline:** keep as a baseline and repository housekeeping
    task. Do not spend time on unrelated polish.
2.  **M0.5 safety/reliability:** complete this document before new
    feature work.
3.  **M1 graphics:** proceed only after M0.5 acceptance. The current
    compositor/ISR issue must be fixed before expanding graphics.
4.  **M2 GUI:** continue after the rendering execution-context and
    synchronization model are sound.
5.  **M3 real hardware:** retain, but validate PMM and memory-map
    handling before attempting physical hardware.
6.  **M4 storage:** retain AHCI/FAT32/VFS goals, but build on the
    validated block I/O and filesystem safety rules.
7.  **M5 userspace:** `copy_from_user`/`copy_to_user` is no longer a
    future M5 item; it is a prerequisite completed in M0.5. Keep ELF and
    libc work here.
8.  **M6--M7:** retain userspace GUI and desktop session goals.
9.  **M8--M10:** keep as stretch milestones and preserve the cut list.
10. **M11 hardening:** use for additional fuzzing, soak testing,
    performance and release hardening---not for first-time fixes to
    basic kernel memory safety or disk integrity.
11. **M12 release:** retain.

### Important adjustment to the original roadmap rules

The original rule says to append new test suites and never edit old
ones. Preserve existing gate coverage, but do not make tests immutable
if a genuine test defect is discovered. Any test correction must be
explained, reviewed, and must not reduce the behavior being verified.
The objective is **no weakened coverage**, not "never touch a test
file."
